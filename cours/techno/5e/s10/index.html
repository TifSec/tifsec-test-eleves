Pour commencer

Reprends les méthodes des séances précédentes si elles te sont utiles ; les rappels du cours t’accompagnent.

Ce que vous allez apprendre

  • Comprendre qu'un programme complexe peut être construit progressivement.
  • Comprendre qu'un événement déclenche des instructions lorsqu'une situation particulière se produit.
  • Comprendre qu'une variable permet au programme de conserver une information.
  • Comprendre qu'une condition permet au programme de choisir entre plusieurs actions.
  • Comprendre qu'il est utile de tester chaque petite fonctionnalité avant d'en ajouter une nouvelle.
  • Comprendre qu'une erreur observée fournit des informations utiles pour rechercher ce qui doit être corrigé.

Mission 7À commencer

7. Le programme doit se souvenir

Lis les repères et observe ce qui est montré

L'objet disparaît maintenant lorsque le joueur le récupère.

Mais une difficulté apparaît :

Comment le programme saura-t-il plus tard que l'objet a déjà été récupéré ?

Nous allons conserver cette information dans une variable.

Ouvrez la catégorie Variables et créez :

objetRecupere

Documentation : Microsoft MakeCode Arcade – Variables

Microsoft MakeCode Arcade – Variables

Cette variable utilisera deux valeurs simples :

  • 0 : l'objet n'a pas encore été récupéré ;
  • 1 : l'objet a été récupéré.

Dans au démarrage, ajoutez :

définir objetRecupere à 0

Puis, dans l'événement Player + Food, juste avant ou après la disparition de l'objet, ajoutez :

définir objetRecupere à 1

Mission 11À commencer

11. Quand un test échoue

Lis les repères et observe ce qui est montré

Si un test échoue, ne recommencez pas immédiatement tout le programme.

Ne modifiez pas non plus plusieurs parties au hasard.

Utilisez la méthode :

Observer → proposer une cause → vérifier → modifier une chose → tester à nouveau

Exemples :

  • l'objet ne disparaît pas → vérifier d'abord l'événement Player + Food ;
  • l'objet disparaît mais la victoire reste impossible → vérifier la valeur de objetRecupere ;
  • le joueur gagne même sans récupérer l'objet → vérifier la condition placée dans l'événement de sortie.
